# BSRU Workshop — ระบบจัดการอบรมและเวิร์กช็อป

## ใช้ Supabase เก็บฐานข้อมูล

ตัวเลือกสำหรับเจ้าของระบบที่ต้องการดูรหัสผ่านจริงใน Supabase อยู่ใน [SUPABASE_PASSWORD_VIEW_TH.md](SUPABASE_PASSWORD_VIEW_TH.md) ต้องเปิดใช้เองและมีความเสี่ยงจากการเก็บรหัสที่อ่านได้

เตรียม `.env` สำหรับใส่ DATABASE_URL และคำสั่ง `npm run db:status`, `npm run db:backup`, `npm run db:migrate` แล้ว ดูขั้นตอนเชื่อมโปรเจกต์เดิมและย้ายบัญชี/กิจกรรมจาก SQLite ใน [SUPABASE_SETUP_TH.md](SUPABASE_SETUP_TH.md) การย้ายไม่ลบต้นทางและไม่เขียนทับปลายทางที่มีข้อมูล

## ระบบสมาชิก: สมัครปกติและส่ง OTP ตอนรีเซ็ตรหัสผ่าน (30 ต.ค. 2569)

สมัครด้วยอีเมลและรหัสผ่านแล้วเข้าสู่ระบบได้ทันที ส่วนลืมรหัสผ่าน/เปลี่ยนรหัสผ่านใช้ OTP 6 หลักส่งไปยังอีเมลที่สมัคร ผ่าน Gmail SMTP ไม่ต้องซื้อโดเมน ข้อมูลสมาชิก รหัสผ่านแฮช และกิจกรรมเก็บในฐานข้อมูลแอป โดยใช้ Supabase PostgreSQL บน production ดูวิธีสร้าง Gmail และตั้งค่าตั้งแต่ต้นใน [PASSWORD_RESET_SETUP_TH.md](PASSWORD_RESET_SETUP_TH.md)

ตั้ง `REGISTRATION_PROVIDER=password` และค่า `SMTP_USER`/`SMTP_PASSWORD` ฝั่งเซิร์ฟเวอร์ แล้ว deploy โค้ดรุ่นนี้ บัญชีเดิมยังใช้รหัสผ่านและสถานะอนุมัติเดิม บัญชีใหม่ได้สิทธิ์สมาชิกทั่วไปทันที การสมัครไม่ขึ้นกับการตั้งค่าอีเมล ส่วนรีเซ็ตต้องมีผู้ส่งที่ใช้งานได้จริง ระบบนี้ใช้ `public.users` ไม่ใช่ Supabase Auth

## การปรับปรุงระบบปิด (29 ต.ค. 2569)

- เข้าสู่ระบบหน้าเดียว ระบบเลือกพื้นที่ผู้เรียนหรือเจ้าหน้าที่ตามสิทธิ์บัญชี
- หน้าแรกผู้เรียนเน้นกิจกรรมถัดไป ชั่วโมงสะสม และแจ้งเตือน; เจ้าหน้าที่จัดการกิจกรรมแบบตาราง
- เปิดรายละเอียดกิจกรรม กรองช่วงวันที่ และแยกสถานะกิจกรรมของฉันได้; URL ใช้ `#workshops`, `#mine` ฯลฯ เพื่อเปิดหน้าตรงและย้อนกลับ
- จำนวนที่นั่งใช้ยอดรวมจากเซิร์ฟเวอร์ โดยไม่เปิดเผยรายชื่อสมาชิกอื่น; ยืนยันสำเร็จหลังบันทึกจริง
- ตรวจเวลาชนกันทั้งหน้าเว็บและ API; แจ้งผู้สมัครเมื่อเปลี่ยนวัน เวลา สถานที่ หรือปิดรับสมัคร
- ประวัติการแก้ไขผ่าน snapshot สร้างจากเซิร์ฟเวอร์และไม่ส่งให้ผู้เรียน
- จำกัดการลองเข้าสู่ระบบต่ออีเมล/เบอร์: 8 ครั้งใน 15 นาที เก็บในตาราง `login_attempts` ทั้ง SQLite และ PostgreSQL
- สมัครและเข้าสู่ระบบได้ตามปกติแม้ยังไม่ตั้งผู้ส่งอีเมล การกู้รหัสผ่านเปิดเมื่อกำหนด SMTP แล้ว และไม่ส่ง OTP กลับมาแสดงบนหน้าเว็บ

Schema จะสร้างตาราง `login_attempts` เมื่อเริ่มแอป หากจัดการ schema ภายนอกด้วยตนเอง ให้ใช้ schema ล่าสุดก่อนเปิดใช้โค้ดรุ่นนี้

ระบบกู้รหัสผ่านเชื่อม SMTP แล้ว แต่ยังต้องตั้งบัญชีผู้ส่งและทดสอบอีเมลจริง บทบาทเจ้าหน้าที่ยังเป็นสิทธิ์รวมตามระบบเดิม ยังไม่มีการแบ่งเจ้าของกิจกรรม, QR เช็กชื่อ, รายชื่อสำรอง หรือใบรับรอง ฟอนต์และไอคอนยังโหลดจากภายนอก จึงยังไม่ใช่การติดตั้งแบบไม่มีอินเทอร์เน็ต

การ Deploy บน Vercel ใช้ PostgreSQL ภายนอก ดูขั้นตอนและค่าที่ต้องตั้งใน [DEPLOY_VERCEL_TH.md](DEPLOY_VERCEL_TH.md)

UI ใช้งานจาก `public/index.html` โดยใช้สไตล์ร่วมใน `public/assets/css/premium.css` ครอบคลุมหน้าผู้เรียนและเจ้าหน้าที่ รองรับหน้าจอมือถือ เมนูผ่านคีย์บอร์ด และการตั้งค่า `prefers-reduced-motion` เพื่อปิด Motion

ระบบ Node.js ใช้ SQLite เมื่อรันบนเครื่อง และ PostgreSQL/Supabase เมื่อกำหนด `DATABASE_URL` เว็บให้บริการจาก `public/` และไฟล์ SQLite อยู่ที่ `storage/bsru-workshop.sqlite` ซึ่งอยู่นอกโฟลเดอร์เว็บ

## สิ่งที่ต้องมี

- Windows 10/11, macOS หรือ Linux
- Node.js 22.13 ขึ้นไปในสาย 22.x หรือ Node.js 24.x (ใช้ `node:sqlite` ที่มากับ Node.js และใช้ Prettier สำหรับจัดรูปแบบโค้ด)

ตรวจ Node.js และ npm ใน PowerShell:

```powershell
node --version
npm --version
```

## พัฒนาผ่าน Terminal

เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน:

```powershell
npm install
npm run dev
```

เปิด URL ที่ Terminal แสดง ปกติคือ `http://127.0.0.1:8001` หากพอร์ตไม่ว่างจะใช้ 8002 โหมด dev จะรีสตาร์ตเมื่อแก้ `src/`, `server.js` หรือ `database/schema.sql` การแก้ไฟล์ใน `public/` ให้รีเฟรชเบราว์เซอร์เพื่อดูผล กด Ctrl+C เพื่อหยุด

- `npm start`: เปิดระบบตามปกติ
- `npm run check`: ตรวจไวยากรณ์ JavaScript
- `npm test`: ทดสอบ API กับฐานข้อมูลชั่วคราวแยกจากข้อมูลใช้งาน
- `npm run format`: จัดรูปแบบโค้ด
- `npm run format:check`: ตรวจรูปแบบโดยไม่แก้ไฟล์

กำหนดพอร์ตด้วย `$env:PORT='8010'` ก่อนรันคำสั่งได้ ฐานข้อมูลหลักยังอยู่ที่ `storage/bsru-workshop.sqlite` และเลือกฐานข้อมูลแยกได้ด้วย environment variable `DB_FILE`

## โครงสร้างโค้ดใหม่

- `public/index.html`: โครงหน้าเว็บ
- `public/assets/css/app.css`: รูปแบบและ responsive layout
- `public/assets/js/app.js`: การแสดงผล ฟอร์ม และการเรียก API
- `public/assets/images/`: รูปภาพที่แยกจาก data URI เดิม
- `src/server.js`: ประกอบโมดูลและเริ่มเซิร์ฟเวอร์
- `src/config.js`, `src/utils.js`: การตั้งค่าและฟังก์ชันร่วม
- `src/database/`: เปิด SQLite และสร้างข้อมูลสาธิตเริ่มต้น
- `src/auth.js`, `src/http.js`: session สิทธิ์ CSRF และ HTTP helpers
- `src/store.js`: อ่าน ตรวจสอบ และบันทึกสถานะระบบ
- `src/routes.js`, `src/static.js`: API และการให้บริการไฟล์หน้าเว็บ
- `scripts/`, `tests/`: คำสั่งพัฒนาและการทดสอบ

`server.js` ที่โฟลเดอร์หลักยังรองรับคำสั่งเดิม ใช้ `public/index.html` เป็นหน้าเว็บหลักเพียงจุดเดียว ผลตรวจล่าสุดอยู่ใน `QA_REPORT_TH.md`

## เริ่มและหยุดระบบ

1. เปิดโฟลเดอร์ `C:\Users\ASUS\Desktop\edu_workshop_test`.
2. ดับเบิลคลิก `start-local.bat`.
3. ระบบลองเปิดที่ `http://127.0.0.1:8001` ก่อน หากพอร์ตไม่ว่างจะสลับไป `http://127.0.0.1:8002` โดยไม่ปิดโปรแกรมอื่น ให้ใช้ URL ที่หน้าต่างคำสั่งแสดง.
4. หน้าต่างคำสั่งจะแสดงตำแหน่งเว็บและไฟล์ฐานข้อมูล ปล่อยหน้าต่างนี้เปิดไว้ขณะสาธิต.
5. หยุดระบบโดยคลิกหน้าต่างเซิร์ฟเวอร์แล้วกด `Ctrl+C`.

เซิร์ฟเวอร์ผูกกับ `127.0.0.1` เท่านั้น ใช้สำหรับ localhost และการสาธิตในเครื่อง ไม่ได้เปิดให้เครื่องอื่นในเครือข่ายเข้าถึง

## โหมด OTP ในเครื่อง

ระบบปัจจุบันส่ง OTP ทาง SMTP จริงทั้งบนเครื่องและ production ไม่มี OTP จำลองในหน้าเว็บ โดยใช้ `REGISTRATION_PROVIDER=password` เส้นทาง Firebase/Resend รุ่นเดิมยังเก็บเพื่อความเข้ากันได้ แต่ไม่ใช้เป็นค่าเริ่มต้น

ในเครื่อง เซิร์ฟเวอร์อ่าน `.env` อัตโนมัติ ค่าที่ตั้งจาก PowerShell มีลำดับความสำคัญสูงกว่าไฟล์ เมื่อแก้ `.env` ให้เริ่มเซิร์ฟเวอร์ใหม่

## ฐานข้อมูล

- Schema: `database/schema.sql`
- ไฟล์ข้อมูลจริง: `storage/bsru-workshop.sqlite`
- สถานะและข้อมูลหลักถูกเก็บใน SQLite; รหัสผ่านเก็บเป็น salted scrypt hash; session เก็บเฉพาะ hash ของ token.
- API ใช้ prepared statements, ตรวจ session/บทบาท และตรวจ CSRF token สำหรับคำขอที่แก้ไขข้อมูล.
- เปิดดูสถานะเชื่อมต่อได้ที่ `http://127.0.0.1:8001/api/health`.

## สำรองและกู้คืน

ปิดเซิร์ฟเวอร์ก่อนคัดลอกไฟล์ฐานข้อมูล เพื่อให้สำเนาสมบูรณ์:

```powershell
Copy-Item .\storage\bsru-workshop.sqlite .\storage\bsru-workshop-backup.sqlite
```

กู้คืนโดยปิดเซิร์ฟเวอร์ก่อน แล้วคัดลอกไฟล์สำรองทับ `storage\bsru-workshop.sqlite`.

## แก้ปัญหาเบื้องต้น

- **พอร์ต 8001 ถูกใช้งาน:** ระบบจะลองพอร์ต 8002 ให้อัตโนมัติ ถ้าพอร์ตสำรองไม่ว่าง ให้ตรวจด้วย `Get-NetTCPConnection -LocalPort 8001,8002 -State Listen`.
- **ไม่พบคำสั่ง `node`:** ติดตั้ง Node.js LTS จาก [เว็บไซต์ทางการ](https://nodejs.org/en/download) แล้วปิด/เปิด PowerShell หรือ File Explorer ใหม่.
- **หน้าเว็บไม่เปิด:** ตรวจว่าหน้าต่าง `start-local.bat` ยังทำงาน และใช้ URL `http://127.0.0.1:8001`.
- **รีเซ็ตข้อมูลสาธิต:** หยุดเซิร์ฟเวอร์ก่อน จากนั้นสำรองแล้วลบไฟล์ฐานข้อมูลและไฟล์ `-wal`, `-shm` ถ้ามี แล้วเริ่มใหม่ ระบบจะสร้างฐานข้อมูลและข้อมูลสาธิตชุดเริ่มต้น.
